# 把粉商小本部署成手机和电脑共用的网址

**当前状态：这里提供部署配置和入口，没有替你创建 Render 服务，也还没有已上线的仪表盘网址。**部署需要你登录托管账号，并确认资源配置。当前 Codex 开发环境不能作为长期在线的公网服务。

使用你现有的 GitHub 账号登录 Render 即可开始，不用先买域名。Render 会为成功部署的服务分配 HTTPS 地址；实际地址以你的服务页面为准，不能从服务名提前推断。

**[打开 Render 部署入口](https://render.com/deploy?repo=https://github.com/xucong78/11)**

这个链接打开的是创建服务页面，**不是已经运行的仪表盘**。配置文件是仓库根目录的 [render.yaml](../../render.yaml)。

## 四步开始使用

### 1. 登录 Render，确认托管方案

打开上面的入口，使用 GitHub 登录或注册 Render。如果出现仓库授权，选择 `xucong78/11`，从 `main` 分支的 `render.yaml` 创建 Blueprint。

确认创建的是：

| 资源 | 用途 | 配置 |
|---|---|---|
| 一个 Node Web Service | 网页、登录、云端数据接口 | `fenbd-dashboard`，`starter`，Singapore |
| 一块持久磁盘 | SQLite 工作区与会话数据 | 1 GB，挂载在 `/var/data` |

**这是带持久磁盘的付费配置。创建前查看并确认服务与磁盘的当前费用；不要把它当作免费方案。**本配置未写死价格，实际金额、付款要求及可用方案以 Render 确认页面为准。如果不接受费用，先不要创建资源，也不要直接去掉磁盘后录入正式数据。

### 2. 部署完成后，取得网址和访问密码

在 Render 中等待服务显示可用状态。打开这个服务页面提供的 HTTPS 地址，这才是以后电脑和手机共同使用的仪表盘网址。

在服务的 **Environment（环境变量）** 页面查看平台自动生成的 `DASHBOARD_PASSWORD`。它是这一个工作区的访问密码；在仪表盘登录页面填写即可。请保存在你自己的密码管理器中，不要发到聊天、写入代码或放进网址。

代码会自动读取 Render 提供的 `RENDER_EXTERNAL_URL` 作为公开来源校验地址，通常不需要手动填写 `APP_ORIGIN`。如以后换自定义域名，再按实际 HTTPS 来源设置 `APP_ORIGIN`。

### 3. iPhone 和电脑打开同一网址

在 iPhone 的 **Safari** 中打开服务的 HTTPS 地址并登录。点 Safari 的分享按钮，选择 **添加到主屏幕**，即可从桌面图标进入。

电脑打开同一网址，用同一访问密码登录，会进入同一工作区。这里只同步你录入的合作记录和检查项，没有自动接入抖音后台订单或达人私信。

### 4. 验证同步，再开始录入正式合作

先新建一条明确标记的测试合作，在另一台设备刷新并确认能看到；再从另一台修改，确认原设备也更新。验证完成后删除这条测试记录。

如果原来使用离线版，先在离线网页的“导入与备份”中导出 **JSON 完整备份**，再在云端工作台导入。CSV 和 Excel 不是完整恢复备份。导入会替换当前云端工作区，请先导出已有云端数据，并在提示中确认；不要把两个有不同内容的工作区直接互相覆盖。

## 云端保存与备份

- 正式数据存储在你这项 Render 服务的持久磁盘中，应用的数据目录为 `/var/data/fenbd`，不存入公开 GitHub 仓库。
- 浏览器可能保留尚未同步的本机草稿。只有界面确认服务端保存成功，才表示该次修改已经进入云端。
- 两台设备同时修改同一个版本会触发冲突提示。先导出未同步内容，再选择如何保留；不要连续强制覆盖。
- 持久磁盘保留期间，正常服务重启和代码重新部署不应清除 SQLite 数据。服务停止期间手机无法访问，停止是否继续计费以平台说明为准。
- 删除磁盘、删除对应资源或把 `DATA_DIR` 改到临时目录，可能造成数据丢失或读到一个新工作区。变更前先导出 JSON 备份，不要用删磁盘来解决登录或启动问题。
- 定期在云端界面导出 JSON，存到公司允许的备份位置。公司真实达人资料、报价、订单和备份不要提交到这个公开仓库。

这是单一工作区的访问密码模式，适合个人跨设备使用。若需要多人独立账号、分角色权限或企业审计，应先扩展权限系统，再作为团队共用系统。

## 部署参数

| 参数 | 作用 |
|---|---|
| `NODE_VERSION` | 固定使用 Node.js `24.22.0`，支持原生 SQLite |
| `NODE_ENV` | 生产运行，启用 HTTPS 会话 Cookie 配置 |
| `DATA_DIR` | `/var/data/fenbd`，必须位于持久磁盘内 |
| `DASHBOARD_PASSWORD` | Render 自动生成的工作区访问密码，至少 12 位 |
| `PORT` | 由 Render 注入，应用按它监听 |
| `RENDER_EXTERNAL_URL` | 由 Render 注入，应用用作公开来源校验 |

## 上线后的必要验收

以下项目需要在**实际部署的 HTTPS 服务**中完成，当前部署文档不代表它们已通过：

1. iPhone 和电脑分别登录，同一条合作的新增、修改、删除能在另一端读到。
2. 未登录或退出登录后，数据接口拒绝读取工作区；页面不会继续显示可访问的云端记录。
3. 导出备份后重启服务，确认之前的合作与检查项仍在。
4. 两端从同一个版本同时编辑时，后保存的一端收到冲突提示，先保存的记录未被静默覆盖。
5. 断网时不会显示“云端已保存”；恢复网络后按提示同步，或导出未同步内容保留。

本配置已按这些公开示例准备并做本地结构检查。当前环境没有 Render 托管授权，且官方部署控制台及 schema 地址的网络访问受限，因此未在 Render 创建、计费、部署或验证线上服务。

# 粉商小本 · 云同步仪表盘

面向达人短视频带货商务的手机与电脑工作台。用户录入的合作信息保存在服务端 SQLite 数据库，同一服务地址登录后可从不同设备访问；不再依赖单个浏览器作为唯一存储。

## 开通在线地址

[使用 GitHub 账号前往 Render 部署](https://render.com/deploy?repo=https://github.com/xucong78/11)

这是部署入口，**不是已开通的仪表盘地址**。需要你登录托管平台、查看并确认服务与持久磁盘方案。创建成功后，平台分配的 HTTPS 地址才是电脑和 iPhone 共用的网址。完整步骤见 [DEPLOY.md](DEPLOY.md)。

## 数据与登录

- 单个私有工作区，由访问密码保护；电脑与手机使用同一网址和密码。
- 密码通过 `DASHBOARD_PASSWORD` 配置，不保存在网页、GitHub、URL 或导出文件中。
- 数据存放在 `DATA_DIR`，生产环境需挂载持久磁盘。仅把程序放进 Codex 云任务、临时容器或没有持久磁盘的托管实例，不等于可靠的长期云存储。
- 多设备同步采用版本校验，冲突时要求先保留本地修改或加载云端数据，不静默覆盖另一个设备的修改。
- 仍需定期导出 JSON；浏览器会显示同步中、已同步、离线或冲突状态。只有服务器成功确认后才显示已同步。
- 这是手工录入业务数据的同步工作台，尚未自动接入抖音订单或达人平台数据。
- 目前为个人工作区，不包含企业成员账号、角色分级或公司审批流。

## iPhone 使用

部署后用 Safari 打开平台分配的 HTTPS 地址并登录，再点分享菜单中的「添加到主屏幕」。仪表盘采用手机布局、底部导航、大按钮和安全区域间距；添加到主屏幕后依然访问同一个云端数据库。

## 迁移旧离线台账

先在旧工具导出 JSON 备份，再在云端工作台的导入功能选择该文件。迁移需要确认，不能把旧浏览器缓存自动当作云数据。Excel 是独立台账，暂不自动导入或同步。

## 本机开发与验证

需要 Node.js 24.5+。应用后端不依赖额外 npm 包。

```bash
cd apps/merchant-dashboard
npm ci
cp .env.example .env
# 用编辑器在 .env 中填写自己的至少 12 位访问密码。
# 本机 HTTP 调试将 NODE_ENV 改为 development；生产保持 production。
npm start
npm test
```

本机 HTTP 调试使用 `NODE_ENV=development`，生产部署必须保留 `NODE_ENV=production`、HTTPS 与安全 Cookie。不要把密码写在脚本或文档中。

浏览器同步验收使用仓库根目录开发依赖中的 Playwright，因此先在根目录运行 `npm ci`，再在本应用目录运行 `npm run test:browser`。测试会自动创建临时数据库与内存中的随机访问密码，结束后清理；当前云环境使用 `/usr/bin/chromium`，其他环境可通过 `CHROMIUM_PATH` 指定浏览器。

浏览器验收覆盖双设备合作跟进、报价参数与 SOP 同步、重启保留、离线冲突、旧 JSON 导入与备份、375/390/430px 手机布局。移动布局通过 Chromium 模拟验证，仍需部署后在真实 iPhone Safari 中检查。

云托管是否已经上线、是否可以从你的 iPhone 登录，以及重启后数据是否仍在，需要在实际部署成功后验证。仓库代码、当前开发机验证与已经上线是不同状态。

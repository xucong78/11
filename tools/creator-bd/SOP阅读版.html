南昌拌粉商家｜达人短视频带货商务 SOP（试运行版）

版本：v0.1。适用岗位：寻找达人、沟通合作、寄样、跟进短视频发布与成交的商家商务。

本文件是入职后校准的执行底稿。产品、售价、成本、佣金、库存、预算及业绩目标均以公司确认的数据为准；文中的节奏是建议试运行值，不是抖音平台规则或对达人单方面生效的约定。

一、先把岗位的交付定义清楚

商务每天要交付的不是“加了多少人”，而是可追溯的合作进度、可执行的下一步、真实发布的合格视频，以及按统一口径复盘的经营结果。

每个推进中的合作必须能回答：谁在负责、合作哪款商品、谈到哪一步、下一步是什么、什么时候完成、成本和承诺由谁批准、结果在哪里核对。

入职第一天，与直属负责人确认

待确认事项要拿到的结论或资料未确认时怎么做
业务目标与边界本岗位负责的店铺、账号、商品；是否兼顾直播、投流、素材授权；月度目标与试用期交付不擅自承诺直播、投流、独家或素材买断
合作方式纯佣、固定服务费＋佣金、其他方式的适用条件；签约主体、流程、审批人先记录达人意向，费用与条款待审批
商务权限可直接确认的事项；超预算、改价、额外赠品、佣金调整、补拍的审批人和审批渠道不把“正在申请”说成“已答应”
产品资料在售 SKU、标签、配料表、过敏原信息、储存条件、保质期、食用方法、批次追溯和质检资料未经证实的卖点不进入对外话术
价格与利益日常价、活动价、券与赠品、达人实际推广链接；公司认可的成本表和最低贡献要求不先报“最低价”“最高佣”
订单与库存发货时效、物流覆盖、产能、可售与可寄样库存、活动预留量、售后承接人库存不足或发货承接不明时暂缓排期
数据与口径精选联盟/店铺后台等必要权限、导出方式、归因与结算口径、退款处理方式不凭达人截图或公开视频播放量确认成交结算
现有资源历史合作达人、重复触达名单、黑名单及依据、已寄未发、待结算、在谈合作先排重，避免多人同时对接、重复寄样

输出：一张《业务参数确认表》，每个字段记录“确认值／负责人／确认日期／依据链接”。未知项保留“待确认”，不能填 0 代替未知。

二、统一记录单位和状态

1. 一条记录对应一次明确的合作

达人 ID：账号稳定标识或主页链接，用于排重；昵称变化不新建达人。

合作 ID：达人 × 店铺／SKU × 本次合作批次。一位达人可以有多次合作，不用旧记录覆盖新结果。

寄样 ID、视频 ID、结算 ID：关联合作 ID。一次合作多包样品、多条视频时分别记录。

最少字段：负责人、达人链接、来源、类目、适配理由、当前阶段、下一步动作、下一步日期、合作商品、费用方式、审批依据、风险标记、最近更新时间。

2. 阶段流转与关闭状态

待筛选 → 待触达 → 已触达 → 洽谈中 → 待审批／待确认 → 待寄样 → 已寄样 → 已签收／体验中 → 待内容确认 → 待发布 → 已发布 → 观察复盘 → 待结算 → 已结算／合作关闭

每条合作只保留一个主阶段；“待回复、改档、补拍、物流异常”等作为阻塞原因，不混成多个互相冲突的主状态。

关闭状态可选：不适配、拒绝、暂缓、无回复关闭、取消合作、履约异常关闭。关闭必须有原因；可重新跟进的记录填写再次联系条件或日期，不直接删除历史。

食品安全、资质、重大投诉、价格库存等问题使用独立风险标记。风险未解除不因“催进度”越过发布或寄样关卡。

四、商品合作卡：拌粉要把“事实”和“好吃”分开

每个推广 SKU 单独一张卡，不用 A 规格的卖点和 B 规格的价格拼成同一个口径。

字段必填内容／证据对外使用边界
商品身份SKU ID、规格、包数／净含量、主图与真实包装、商品链接包数、重量、赠品说清楚，不混淆“单包价”和“整单价”
原料与过敏原以标签、供应商和公司核验资料为依据的配料与提示不凭口感推断配料；过敏原不确定时交产品负责人确认
烹饪方法干粉／湿粉等实际产品形态；煮、泡、拌等必要步骤和用水条件不把一种规格的操作时间套给另一款；方便性演示保留实测条件
口味与场景真实体验反馈；辣度、份量及香气属于体验描述的部分不承诺所有人都能接受；宿舍、旅行等场景要符合实际准备条件
产地与工艺产地、生产主体、工艺或地方关联的可验证资料“南昌风味”不自动等于南昌生产；“正宗”等表述先核对依据和公司口径
储存与保质标签条件、批次、保质期、开封后要求不擅自延长保存期，不省略需要消费者知道的储存条件
价格与活动标价、券、包邮条件、地区限制、有效期、库存价格按当前条件核对；“最低”“全网最便宜”等说法不能凭感觉承诺
其他声称如营养、添加、认证、检测等主张的适用依据不无依据使用减肥、治疗、保健、零添加、绝对化效果等表述；有疑问交有权人员审核

每条对外卖点记录：表达原句、适用 SKU、证据位置、核验人、核验日期、失效或复核条件。达人个人体验和品牌可证明的产品事实分栏保存。

五、达人筛选：先匹配，再判断成本

1. 建议的试点分层

优先验证：内容与人群适配，愿意真实试吃，近期表现与更新节奏可解释，成本在批准范围，有明确交付承诺。

补资料后判断：缺成交／退款／报价或履约资料；不是“数据缺失就按 0 算”。

暂不合作：商品与人群明显不匹配、无法满足必要事实表达、成本无法批准、已有可核实的严重履约问题等。

2. 每位达人至少看这些维度

1. 类目与人群：是否有食品、速食、拌粉等相关表达经验；受众需求、消费价格带与产品是否吻合。粉丝总量只作背景。

2. 内容稳定性：在同一时间区间内，选取规则一致的近期相关视频，记录样本数、时间、是否含广告；看中位表现与波动，不只挑最高的一条。

3. 互动质量：评论是否讨论产品、口味、购买和食用场景；异常重复、与内容不相关的互动列为核验点，不仅凭一个比率认定造假。

4. 真实商业结果：在合法授权和可获得范围内核对相关商品成交、退款与结算；明确数据是公开视频、达人提供，还是后台可核验。不同来源不混成同一可信等级。

5. 履约与协作：回复、试吃、排期、修改边界、挂链及以往履约。合作条款应清楚，不以无边界免费修改作为“配合度”。

6. 全部合作成本：固定费、预计佣金、样品商品成本、寄样运费、额外制作、经批准投流、素材授权和税费；不能只比较达人报出的单项价格。

可采用“适配／数据／成本／履约”分项记录与证据，不建议入职第一天就用一个未经验证的总分自动淘汰达人。先人工复核小批量，再用真实合作结果调整权重。

六、谈合作与费用测算

1. 合作确认单至少包含

达人主体与账号、合作 ID、店铺及 SKU、样品内容、合作方式、视频条数与规格、发布日或时间范围、挂链与保留要求、事实核对流程、修改和补拍范围、取消／延迟／未履约处理、固定费及支付节点、佣金比例及适用订单、税费发票、数据反馈方式、素材授权范围及期限、投流权限、审批记录。

不把“不保证成交的内容交付合作”默认理解为“必须产生某个 GMV”；如果有绩效条件，必须事先明确具体定义、取数、周期与处理方式。

2. 固定费、纯佣和寄样成本分开看

纯佣合作：佣金通常随有效业务结果变化，但样品、寄样和其他已发生成本仍可能无法收回，不等于零成本合作。

固定费＋佣金：固定费是单独的投入与履约义务，不能直接用 GMV 当回报；佣金计提基数按合同和后台核对。

样品：记录实际商品成本与寄样运费，不能用零售价代替成本；退回、补寄、物流赔付各自留记录。

投流与素材授权：另有预算和权限。允许达人发布，不自动等于允许商家任意剪辑、搬运或投流。

3. 先做保本估算，再按实际对账

统一使用公司财务认可的含税／未税、退款和收入成本口径。下面只是计算结构，不代表任何一家的实际利润：

每有效订单贡献 M = 每单净收入 - 每单商品成本 - 每单履约及售后变动成本 - 该单实际佣金 - 其他每单变动费用

本次固定投入 F = 固定服务费 + 样品实际成本 + 寄样运费 + 额外制作／授权费 + 经批准的本次其他固定投入

当 M > 0 时，可作简化试算：保本有效订单数 = 向上取整(F ÷ M)。

当 M ≤ 0 时，不能靠无限增加订单“摊薄”解决；先调整价格、商品结构或合作成本，或取得负责人明确批准的其他经营目标。输入缺失时显示“待补数据”，不要显示虚假的保本值。

注意：

上述“有效订单”是需要公司定义的测算单位，并不等于平台天然统一的指标；部分退款、多件订单、运费和补贴会改变结果。

不要把已包含退款影响的净收入再扣一次同笔退款；样品计入固定投入后也不要再作为普通订单成本重复扣除。

实际佣金计提基数、平台费用、账期与冲回以合同和对应后台记录为准，不统一假设所有项目都按支付 GMV 的同一个百分比计算。

至少看基准、成本上升／退款上升、成交不及预期三个情景；假设和来源必须可见。

归因 GMV、平台最终结算与业务真实增量不是同一个概念，不能只靠后台归因断言新增销售全部由这条视频带来。

以下是内部试运行建议，入职后与仓储、运营、财务及达人共同校准，不作为平台规定或未经同意的合作条款。

达人明确回复原则上 1 个工作日内给出回应或明确答复时间超出本人权限及时提交，不给未经批准的口头承诺
寄样审批完成按仓储确认的截单与发货周期交接库存或发货延迟提前告知受影响达人并调整排期
快递显示签收可在 1 个工作日内确认包裹与体验安排破损、漏件、错货建立异常单，先解决样品问题
即将发布按双方约定在发布前一个合适的工作日确认内容、库存、链接和档期未确认／有风险则协商改档，不默认对方必须按商家临时要求发布
超过约定发布日期当日了解原因，明确新日期及下一步；不要连续催促多个联系人持续失约由负责人按确认单处理，保留沟通与损失记录
已发布发布当天验收链接与商品链路；可设 D+1、D+3、D+7 初步观察点观察点不是平台归因或最终结算期限；数据未成熟不提前认定利润
结算临近按约定账期提前准备对账资料差异单独列出，不以“达人催得急”为由越权付款

必须升级的异常

类型先做什么升级对象与关闭证据
疑似食品安全、标签、资质或严重质量问题暂停受影响批次寄样与相关推广推进，保存批次、订单和反馈；不让商务自行下最终结论产品／质量负责人、直属负责人、客服；记录核查结论、处置范围与恢复批准
突发缺货、价格错误、发货承接失败标记受影响合作与已发布链接，通知运营和对应达人协商调整店铺运营、仓储、负责人；以链接修正、库存／发货确认和沟通记录关闭
内容包含无法证明的产品主张列出原句、证据缺口和受影响版本，按合作约定及时沟通修正产品／合规负责人；保留修正版及确认记录
未按约定发布、删视频、挂错链核实事实，保存时间与链接，先联系既定合作人；按确认单商议补救直属负责人；以补发、纠正、退款／费用处理或正式关闭决定结束
佣金、固定费、归因或退款争议锁定对应合作版本、订单区间与报表，不先重复付款财务、负责人，必要时法务；以双方确认的差异处理及付款凭证关闭
收件信息或个人数据误发停止继续转发，向内部指定负责人报告，并按公司流程处置数据／信息安全或直属负责人；记录影响范围、处理与权限调整，不公开传播详情

异常单统一字段：异常 ID、合作 ID、发生／发现时间、事实及证据、影响范围、临时措施、主责、升级人、承诺处理时间、最终结论、关闭依据。重大问题优先处理，不等日报。

八、日、周复盘：把过程和经营结果分开

每日工作顺序

1. 上班先看：今天应完成、已经逾期、发布与签收节点、库存与价格变更、待审批和重大异常。

2. 推进存量：先处理已答复、已寄样、即将发布等已有承诺，避免只追求新增触达。

3. 扩充新合作：按筛选规则补充候选，分时段进行有针对性的沟通并及时记录。

4. 下班前清账：每条推进中合作都有下一步和日期；当天新增、状态变化、费用变化和阻塞有记录。

日报可以直接用这四行

今天完成：按合作 ID 列出阶段实际变化，不只写联系人数。

明天优先：到期动作、发布、寄样与审批清单。

需要协助：问题、影响、所需决定、建议选项、最迟决定时间。

经营观察：已成熟窗口的数据、异常和待核验信息；区分估算、后台数据与最终结算。

每周看两张漏斗，不混分母

合作漏斗：去重新增候选 → 已触达达人 → 已回复达人 → 已确认合作 → 已寄样 → 已签收 → 已发布 → 已完成对账。

内容与成交漏斗：合格发布视频 → 有效曝光／播放 → 商品点击 → 支付订单 → 按定义的有效订单 → 最终结算与贡献。

每个比率注明：分子、分母、去重规则、时间范围、数据来源和成熟状态。可采用两种并行视角：

批次视角：同一周首次触达的达人，后续持续追踪；适合看真实合作推进效率。

发生视角：本周真实发生的寄样、发布、成交与结算；适合安排资源和看当前产出。

不要把“本周发布人数 ÷ 本周刚寄样人数”当作同批次出片率。订单、达人和视频也不能混用同一个计数单位。

建议复盘指标：去重触达数、有效回复率、合作确认率、签收后出片率、按约发布率、阶段停留天数、单个合格发布成本、样品投入对应的有效产出、有效订单、退款与售后、实际佣金、完整成本贡献、结算差异率。指标是否能取到、口径与目标由团队确认，先有基线再设目标。

九、入职后的前五个工作日怎么做

时间重点任务当天可交付成果需要负责人确认

十、30 天试点与工具建设顺序

第一周：先形成真实工作底账

以公司批准的小批合作验证 SOP；所有关键承诺、样品和费用可追溯。建立数据缺口和阻塞清单，不先设置未经验证的自动化筛选阈值。

第二周：观察履约与内容承接

关注签收体验、内容事实、挂链、库存、实际发布。记录每个阶段耗时与返工原因，用实际问题调整话术、商品卡与协作责任。

第三周：用成熟数据看成本和转化

对已到观察窗口的同批次合作做复盘；未到窗口的标为进行中。区分达人适配问题、内容问题、商品／价格问题、物流售后问题，不能全部归因给商务或达人。

第四周：选择值得复制的流程

根据真实履约和经营数据，决定复投名单、暂停事项和下一批试点；交付 SOP v1.0、字段字典、口径说明、审批模板及一页复盘。放量需要商品和团队承接能力与预算共同批准。
